# 控制论技能修正记录

本轮依据用户“开始修正”的授权，修正前轮审视提出的具体规则冲突。基线取自当前工作树，保留原有未提交修改；没有用 Git HEAD 覆盖用户工作，没有提交或推送。

## 已实施的契约

| 原问题 | 修正后的行为 | 主要位置 |
| --- | --- | --- |
| 预算耗尽写成完成 | 预算只触发重评；缺验收的任务保持未完成，独立工作可推进 | 执行技能、子代理开发技能与模板 |
| 到上限才准裁决误报 | 每轮按原始证据接受、驳回或补观测，误报与已修复分开记录 | 子代理开发、请求评审及复评审模板 |
| diff 外发现自动非阻塞 | 搜索范围控制成本；已发现问题按后果和当前验收依赖分诊，严重项阻塞交付 | 复评审、最终评审与请求评审 |
| 旧完成标记等同当前事实 | 恢复核对计划内容、任务验收、提交效果、工作树、环境与证据失效条件；只重开受影响部分 | 两种执行技能 |
| 流程只能升级、技能无依据加载 | 按证据选择与收缩流程；保持验收，避免关键词或模式切换触发不适用流程 | using-superpowers、brainstorming |
| 全停或不许停的冲突 | 按必要输入、授权、能力和依赖暂停；沿用已有授权，保留显式逐阶段审阅 | 设计、计划、接收评审与执行技能 |
| 次数直接推断架构或自动换模型 | 先校验反馈通道与竞争假设；预算触发重评，不替代根因证据 | 调试、子代理执行技能 |
| 技能测试只测规则服从 | 用户结果、代价和边界决定验收；服从仅诊断，开放式元测试与有界对照 | writing-skills 及相关参考 |
| 修正文档后无反馈 | 修正后复核受影响约束、接口和引用，避免无差别重复评审 | brainstorming、writing-plans |

恢复规则是代理必须执行的核对契约，本轮没有把工作区脚本重构成自动状态验证器；台账与路径仍只是线索。

## 观察与限制

路由对照中，旧版坚持架构路径、全部暂停评审事项及先讨论架构，新版分别按新证据缩小流程、推进独立事项、恢复可信运行反馈。已有授权场景两版均直接推进。追加边界验证确认用户明确要求审阅时仍等待，纯阅读进入 plan mode 不触发设计流程。

执行组旧版探针已主动拒绝有问题的旧条款，因而没有复现目标违规；新版符合修正后的契约。这支持文本一致性和本次场景决策，不能宣称行为改善。技能测试组旧新版都诚实处理未复现与证据；新版按风险预算、用户结果及指南关键前提决策。

探针使用普通独立子代理和默认继承路由，每版本每组为一个上下文中的复合决策样本；不是生产任务端到端验证，也不是独立重复采样。不估计普遍成功率，不宣称实际时间或费用降低。首次技能测试提示被 read 返回截断，未包含完整任务，已保留为无效记录并在分段完整读取后重跑，不计入对照。

参考材料的最终一致性修正仅作静态与独立评审，未冒称已被之前的行为探针覆盖。工具已加载进现有会话的历史文本不会被回溯替换；本工作区技能入口实际链接到项目源码，后续加载会读取修改后的内容。
