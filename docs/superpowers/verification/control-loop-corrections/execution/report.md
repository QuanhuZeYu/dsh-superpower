# 执行与评审控制契约修正报告

已在分配范围完成正文、流程图、示例、提示模板及简报解析脚本修正，保留既有工作区改动，未 checkout/reset/commit/push。

## 改动

- 完成必须由当前验收与有效证据支持；修复轮次或预算用完只触发重评，未满足项保留未完成。
- 任意轮次都能凭反证裁定误报；争议未解不能作为误报丢弃。
- 复评审范围控制搜索投入；已发现的范围外严重问题或当前验收依赖仍阻塞，最终轮无次数豁免。独立次要改进可后续处理。
- 恢复必须核对计划/规格版本、任务验收、完成提交效果、当前工作树与依赖配置、证据适用范围和失效条件。路径匹配、提交存在、台账完成行都不是跳过充分条件。
- 模型升级或连续失败只是干预/重评信号，不自动证明架构根因。
- 必要输入、授权或能力缺失时暂停依赖步骤，独立已授权任务继续。实现报告状态、请求评审入口和示例同步。
- 保留工作区定位与 task-done 实现，不重构存储。task-start 最小修复兼容 task-brief 当前中文输出和旧英文输出。

## 脚本实际回归

[测试代码](test_task_start.py) 实际运行生产 task-brief CLI 取得中文输出，再传给实际 task-start.main；只隔离 git HEAD 与工作区定位副作用。

- [修改前原始输出](before-script-output.txt)：目标失败为 `task-brief.py 没有报告简报路径：已写入 …task brief.md：2 行`，说明真实输出协议未被识别。
- [初次修改后原始输出](after-script-output.txt)：生产者输出格式、旧英文兼容、无有效简报拒绝通过。独立评审随后指出这尚未覆盖真实 wrapper 的编码边界。
- [编码缺陷真实失败](encoding-before-output.txt)：通过真实 task-start → task-brief → sdd-workspace 入口，在 `PYTHONIOENCODING=gbk`、`PYTHONUTF8=0` 父环境下，中文协议变成替代字符而失败。
- 最小修复仅复制子进程环境并设置 `PYTHONIOENCODING=utf-8`，保留其它变量。[同场景通过](encoding-after-output.txt) 后再扩展中文加空格工作区，[最终原始输出](encoding-final-output.txt) 通过全部现有用例，并核对返回的 brief 路径可打开、内容正确及 BASE。fixture 真实 git init，HEAD 只用于定位的占位值，没有创建提交。
- 这些脚本缺陷有真实失败与修复后通过，和文档基线未复现严格分开。
- [运行方式](run-notes.md)：可复现命令、环境与隔离边界；无 PowerShell。

## 未验证限制

独立决策仅覆盖本组模拟场景的前后各一次运行；未验证模型总体遵守率、跨模型稳定性或真实长计划执行。真实脚本入口已覆盖当前宿主下的简报提取、工作区定位与 BASE 返回，但不等于验证 task-done、业务验收有效性或所有 Windows 区域编码。新恢复契约要求代理/人工核验，脚本不会自动验证计划指纹或所有验收。最终局部修正交父层独立复评审，本报告不预先声称其通过。
