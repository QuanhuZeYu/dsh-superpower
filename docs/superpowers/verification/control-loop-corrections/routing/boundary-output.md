**场景一：只读审视，需要多步骤计划，准备进入 plan mode。**

- 当前动作：列出与只读审视目标相称的调查、分析、证据核查及汇报步骤，可按需要进入 plan mode，继续已授权的只读工作。仅因有多步骤计划或模式切换，不启动 brainstorming，也不套用面向代码实施的 writing-plans 流程。
- 暂停范围：没有额外设计审批导致的暂停。行为修改与项目写入不在该场景授权内，不能执行；只读审视本身无需停下等待行为设计认可。如平台模式确有必要确认，只处理该模式要求，不把它扩大为行为修改授权。
- 理由：using-superpowers 明确规定，进入 plan mode 前仅在“需要创建或改变行为、且设计尚未明确”时加载 brainstorming；纯阅读、审查不因切换模式新增设计流程。用户的多步骤审视需求足以支持制定只读工作安排。

**场景二：用户要求逐阶段审阅，调查证明可从架构任务收缩为一处参数修复，修正方案尚未审阅。**

- 当前动作：据已取得的只读证据重新分类为有界工作，说明支持降级的影响范围、依赖、剩余未知及保留的验收；更新既有清单。在对话中提交可评审的简短修正设计，写清拟改参数、预期行为、涉及位置和验证方法，请用户完成本节点审阅。题面未给出具体参数值，决策中不编造它。
- 暂停范围：等待该次审阅，暂停参数修改以及依赖该方案认可的后续实施、交付步骤。独立且已获授权的只读核查、证据整理和评审准备可以继续；不得一边等用户审阅一边先改参数。降级后无需继续制作不再适用的架构规格及独立实现计划文档，但必须保留用户明确要求的审阅节点。
- 理由：brainstorming 允许按证据收缩流程，却明确规定“路径变化不自动扩大授权，也不能用于跳过失败验收或用户明确要求的审阅”。用户要求逐阶段审阅时，“到约定节点呈现可评审产物，等待该次审阅”。这是本场景实际暂停的依据。只读调查支持范围判断，不等同于修复已通过真实行为验证。

**场景三：已授权在既定范围自主实施，架构性规格自审通过，下一步编写计划，未要求逐阶段审阅。**

- 当前动作：提供规格链接并说明进入计划阶段，加载并使用 writing-plans 编写实施计划；计划继承规格的目标、范围、约束和验收，按剩余不确定性确定深度并完成自检。无需再询问“是否认可规格”或“是否可以开始写计划”。计划完成后，只要目标、风险、范围及必要输入未变化，沿用既有授权和执行方式继续；未指定方式时按任务依赖、成本及可用工具作出合理选择并说明。
- 暂停范围：当前无需暂停。后续若出现超出授权、改变目标或外部契约、不可逆后果或缺少必要用户决定，只暂停受影响步骤，先完成独立的已授权准备。不得仅因跨阶段或生成新文档而增设用户审批。
- 理由：brainstorming 的规格交接明确写明：“用户要求该节点审阅时等待回复；已授权自主推进时继续编写计划。”writing-plans 也要求沿用已有授权与评审约定。自审通过与自主授权足以推进此场景，但必须准确称为“规格自审通过”，不能声称“用户已审阅”。
