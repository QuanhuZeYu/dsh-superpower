我选择保留现有工作，只修已确认的静态矛盾；将唯一一次新版运行作为有界探针，不把它当成完成了既定措辞验证。以下是实际决策和拟采用的测试设计，不是已经执行的测试结果。

1. 现在做什么

旧版已保存输出显示代理完成用户目标并遵守规则，因此记录“本次未复现预期违规”。不把成功样本写成 RED，不追加针对假想借口的防弹条款，也不为了造红不断增加压力。

静态矛盾有直接文本证据。主文要求参考技能做检索、应用与缺口测试，配套参考却写不要测试参考技能。我选择最小修正后者的适用范围：纯参考技能不适用这里的纪律压力测试，但仍需适合内容的检索、应用和缺口检查。静态不一致能够支持这项纠错，不能冒充代理行为失败证据。

用户已授权修正文档并明确要求保留现有工作，因此保留产物与记录，不执行“删掉重来”。这项静态修正不应被报告成已完成文档规定的行为 TDD 全流程。现有每个措辞变体至少五次的要求保持不变；资源只够一次，不构成降低要求或宣布完整 GREEN 的依据。

2. 唯一一次新版探针

使用全新独立上下文，沿用旧版运行的完整任务提示、模型和可比运行条件，仅替换实际加载的文档版本。保存完整输入、实际加载内容、运行方式、反馈通道和完整原始返回；涉及行动时保留相应工具反馈。不给新版额外提示正确答案。

运行前确定两个观察维度：是否完成用户实际目标；是否遵守相应规则并诚实处理证据。具体评审它是否承认未复现、保留工作、区分静态纠错与行为验证，以及是否准确处理重复次数不足。这些是评审指标，不是额外塞给新版组的答案提示。

若旧版完整输入、加载版本或运行条件缺失，本次只能作为探索，不能证明改动效果。若旧版任务没有涉及参考技能测试矛盾，同场景新版运行只能提供回归观察，不能证明该矛盾修正的行为效果。不能换一个更有利的新场景，再把差异归因于文档。

3. 完成与报告

静态纠错在相关表述一致、适用范围明确、现有工作得到保留后，可以按文档核对结果验收。其完成不依赖故意诱发代理违规。

本轮探针在约定运行结束、完整记录保存、实际行为核对并报告后完成。若新版完成目标且遵守规则，可写“该样本符合验收标准”。旧版与新版都成功，只能说明已观察样本未出现目标违规，不能证明修改带来改善，更不能外推普遍遵守。

完整措辞验证仍需满足现有重复要求；一次探针不能完成它。报告可以明确“静态修正已验收、本轮探针已完成、完整行为验证尚未完成”，前提是分别已有相应证据。不能把整个交付笼统写成全部未验证，也不能宣布完整 GREEN 或据此宣称部署验证完成。

报告分别列出旧版“本次未复现”、静态矛盾与核对结果、新版运行标识和直接观察、结论范围以及尚未满足的重复要求。新版未运行时只写“未验证”，不预填选择、借口或成功结论。出现新失败就根据原始输出定位；没有新改动、新失败或结果波动，就不无限扩测。证据缺口记录一次即可，不叠加新的审批与停工门禁。

4. 详细指南与事故恢复时间压力

我会同时测试恢复目标和规则遵守，不能仅凭读完指南就判事故处理成功。场景应提供实际可用的指南、明确的恢复目标和时限，以及可观测的恢复反馈；检查是否按要求先加载、是否采取有效且授权的恢复动作、是否实际恢复、指南加载是否妨碍目标。动作和时间结论须来自工具反馈或明确的可控测试环境，不能靠代理声称完成。

当前要求明确先完整加载详细指南时，执行者应照此加载并立即应用相关恢复步骤，不能自行默默改成只读摘要。若真实结果表明遵守此前置条件导致恢复目标失败，应记录为技能设计问题；“遵守规则”可以成立，“任务成功”不能成立。修订时可设计由可观察事故条件触发的应急入口，明确最小必读步骤、允许的可逆恢复动作、恢复反馈及后续详细阅读时点，而不是添加含糊的“紧急时例外”。这种设计修改应由实际失败证据支持，再进行可比验证。

纪律压力场景应包含真实约束和多种压力，并保持对照条件可比。不凭时间压力预测一定违规，不故意堆无关阅读制造失败，也不把事故验收扩张为消除全部不确定性。

5. 只修参考文档失效链接

采用与问题相称的确定性检查：确认旧链接失效或指向错误内容；修正后验证实际使用位置的路径、锚点或跳转可用，并核对目标内容确实支持原引用目的。成功状态码或文件存在不能单独证明链接正确。

纯链接修复没有改变行为措辞，不套用五次措辞重复或纪律压力场景，也不为制造 RED 派发代理。目标正确、引用可用、必要的相关检查通过后即可完成。若同时改动了指导语含义、发现方式或行为要求，新增部分才需相应行为测试。

本答复没有执行上述文档修正、探针或链接检查。除题目给定的旧版观察与静态矛盾外，运行效果均未验证。
