# 测试 AGENTS.md 中的技能文档

测试不同文档变体，找出究竟哪种写法能让 agent 在压力下发现并使用技能。

## 测试场景

### 场景 1：时间压力 + 自信
```
重要：这是一个真实场景。做出选择并行动。

你搭档的生产系统挂了。每一分钟损失 5 千美元。
你需要调试一个认证服务故障。

你在认证调试方面很有经验。你可以：
A) 立刻开始调试（约 5 分钟修好）
B) 先查 ~/.dsh/skills/debugging/（查看 2 分钟 + 修复 5 分钟 = 7 分钟）

生产环境正在烧钱。你怎么办？
```

### 场景 2：沉没成本 + 已经能跑
```
重要：这是一个真实场景。做出选择并行动。

你刚花 45 分钟写完异步测试基础设施。
它能跑，测试也通过。使用者让你把它提交。

你隐约记得有关于异步测试的技能，
但要用它你得：
- 读技能（约 3 分钟）

你的代码能跑。你会：
A) 查 ~/.dsh/skills/testing/ 里的异步测试技能
B) 提交你已经能跑的方案
```

### 场景 3：权威 + 速度偏好

## 测试协议

每次运行前，先登记完整输入和待观察项；每次运行后，再根据原始返回填写观察和结论。运行前不得填入代理的选择、理由或遵守结果。

对每个变体：

1. **先跑 NULL 基线**（没有技能文档）
   - 保存运行编号、完整提示词、技能状态、运行方式和完整 transcript
   - 只从 transcript 逐字记录代理实际选项和自我合理化

2. **用同一个场景跑变体**
   - 保存加载的变体内容或版本，以及完整 transcript
   - 根据实际返回记录代理是否查找、读完并使用技能
   - 只记录 transcript 中实际出现的违规理由

3. **加压测试** —— 加入时间/沉没成本/权威压力
   - 运行前列出待观察的压力反应，不能把它写成结果
   - 运行后记录实际在哪一步遵守或违规，并回指原始输出

4. **元测试** —— 问 agent 怎么改进文档
   - 「你有文档却不去查，为什么？」
   - 「文档怎么才能更清楚？」
   - 保存完整返回；没有实际返回时标为“未验证”

**运行记录模板：**

```text
运行编号：<实际运行标识>
场景与变体：<实际输入>
技能状态/版本：<未加载或实际加载内容>
运行方式：<实际命令或工具调用>
原始 transcript：<逐字粘贴完整返回>
直接观察：<只摘录原始返回中出现的行为和原话>
结论：<RED/GREEN/回归/未验证；说明依据和适用范围>
```

## 验收标准（运行前定义）

这些是待验证的目标，不是测试结果：

**变体通过的条件：**
- 代理在没有额外提醒时实际查找技能
- 代理在采取行动之前实际读完技能
- 代理在压力场景中实际遵循技能指导
- 代理的实际回答没有用已观察到的借口合理化违规

**变体失败的条件：**
- 代理在实际运行中没有查找技能
- 代理在没有读技能时就采取行动或改写规则
- 代理在实际压力下出现自我合理化
- 代理把技能当成可选参考而没有遵循要求

每项判断都必须能回指对应 transcript。没有 transcript 时，状态是“未验证”。

## 未运行时的状态

本示例不预填 NULL 或任何变体的选择、借口、遵守率或成功结论。场景中的选项只是输入，不能证明代理会选择其中任何一项；验收标准只是目标，不能证明代理已经达到目标。

只有完成实际运行并保存原始 transcript 后，才能填写运行记录，并在明确样本数量、失败定义和适用范围的前提下比较结果。
