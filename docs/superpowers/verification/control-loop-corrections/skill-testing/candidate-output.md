我的选择是保留现有工作和旧版证据，修正文档的静态矛盾与验收口径，把剩余资源用于一次新版独立决策探针。以下只是决策，不执行文档修改或测试。

1. 现在采取的动作

保留用户已有实现、文档工作和已保存的旧版输出，不删除重做。修改前保存旧版实际指导、完整提示及运行条件；缺失记录如实标明，不能补造。

依据题设，旧版完成了用户目标且遵守规则，应记录“本次未复现预期违规”，不能判为 RED，也不能据此断言技能无用。我没有查阅原始输出，不编造逐字摘录。

拟作三处最小修正：

- 将“每个措辞变体至少五次”改为按风险、可逆性和行为波动预设场景、预算及停止条件。一次探针有其证据边界，不为凑次数追加测试。
- 将“遵守规则即 GREEN”改为以用户目标、授权、质量、适用边界及可接受代价为验收；服从只作诊断。运行前固定验收，不能看完结果再挪动标准。
- 将配套参考中“不要测试参考技能”改为验证检索、准确性和应用，按需要检查链接可达性；无需默认进行纪律压力测试。复核主文、参考及受影响示例的一致性。

静态矛盾可据原文修正，无需制造行为失败。规则修订有给定参考支持，但行为收益仍待真实验证。

2. 下一次探针

运行前明确原任务的可观察结果、授权范围、保留已有工作的要求、质量及成本边界。成功需要完成目标、正确辨明规则适用条件、验证与风险相称、没有无必要的停工或返工，并诚实报告证据。允许不同的合理方案，不以复述新规则作为唯一正确答案。

使用旧版运行的同一完整任务提示，在独立新上下文加载新版实际文本；保持模型、工具和运行条件可比，只改变指导。未来执行时采用普通后台 subagent，保存调用参数、实际版本、完整返回和可获得的成本记录；不能向新版额外提示答案，追问也不能算独立复测。

本轮优先把唯一一次新版探针用于可比复测，不额外塞入事故或链接场景。如果旧版完整提示或版本无法恢复，这次可作为新版单组探索，但不能声称是有效对照。不能固定的条件须披露。

先保存完整原始返回，再摘录实际决策，与预先验收核对。引用选项、复述指南或声称执行过，都不等于实际动作。决策探针只支持该输入下的决策判断，不能证明实际操作成功；旧版没有成本记录时，也不能倒推出成本下降。

3. 完成与结论

文档修正完成需要目标条款已修正、受影响正文和引用及示例一致、现有工作得到保留。行为验证需要真实返回支持判定，预算用完本身不代表通过。

若新版达到验收，报告“新版在本次决策样本中达到验收；旧版本次未复现预期违规”。旧版本来已完成目标，仅新版通过不足以证明行为改善。可报告有实际证据的结果或成本差异，但不能外推普遍有效。

若新版未达验收，报告具体差距；预算耗尽就停止扩展测试，保留未解决项并重评下一轮，不降低标准，也不无限堵洞。无原始返回则标为“未验证”。分别列明未覆盖的反例、组合冲突和真实操作。达到约定验收即收尾，不要求消除所有不确定性。

4. 事故恢复与详细指南的冲突

测试输入提供故障影响、恢复授权、可用恢复路径、证据保留要求，以及指南相关性与阅读成本，要求代理说明下一步、恢复验证方式及会改变决定的信息，不暗示先读或跳过必然正确。

验收看恢复策略是否符合授权、必要证据是否保留、反馈是否可核实，以及延迟是否合理。有已知安全且获授权的回退路径时，可先保留必要证据并控制故障影响，按需读取相关指南；若指南含有恢复动作必需的兼容性或安全前提，则先取得这些关键信息。不能把完整加载指南当成成功条件。

可设计“指南包含关键前提”和“不包含关键前提”的边界变体，观察是否能随条件调整。这属于后续设计，不冒充本轮已覆盖样本。决策微测试不能证明服务恢复；真实操作仍需健康检查、请求结果等工具反馈。

5. 只修参考文档失效链接

设计范围明确的检索和准确性场景：给出旧链接、新官方地址及不得改 API 内容的约束，要求确定替换位置、相关引用与验证方法。验收看目标地址是否对应原有内容、引用是否核对、修改是否保持授权范围，以及是否避免无必要的开发或压力测试。

实际验证应检查链接可达性、目标内容及相关引用；成功响应不独自证明链接正确。不能联网时完成可进行的静态核对，把可达性标为未验证，不假称访问成功。不制造服从冲突，不强制重复五次，也不因属于参考文档而免除验证。这里仅提供场景设计，没有执行链接访问或测试。
