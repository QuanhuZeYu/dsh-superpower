# 控制论：以反馈驱动任务收敛

**核心闭环：观测 → 判断状态与误差 → 采取最小有效动作 → 验证反馈 → 修正 → 重复（达标即停）。**

## 最小闭环要素

| 要素 | 关键判断 |
| --- | --- |
| **目标与边界** | 需要什么可观察结果？授权范围与不可破坏的约束是什么？ |
| **当前状态** | 已观察到什么事实？哪些只是推断或未知？证据对应哪个版本与环境？ |
| **误差** | 当前结果距验收标准差在哪里？缺少什么关键信息？ |
| **动作** | 哪个最小、可逆、可验证的动作能缩小误差或区分竞争假设？ |
| **反馈** | 从哪里观察结果？什么现象会推翻当前判断？ |
| **退出** | 何时完成交付、重评策略，或因缺少外部输入而暂停？ |

## 七条行动原则

1. **先观测，后行动：** 区分事实、推断与目标；用行动消除不确定性，不把假设当事实。
2. **以误差驱动：** 每个动作必须指向具体差距或待验证假设，不机械走流程。
3. **小步控制：** 优先局部、可逆、可验证的动作；动作幅度与风险和证据强度相称。
4. **行动必有反馈：** 工具调用成功只代表操作已执行，验收必须核对目标状态。
5. **异常立即重评：** 反馈与预测不符时停止扩大改动，更新假设并做最小辨别实验；通道未命中时先修观测通道。
6. **避免过度控制：** 确认、计划、评审和测试按实际风险与剩余不确定性选取。
7. **持续收敛：** 满足约定验收即收尾交付，不为局部完美继续扰动系统。

## 让反馈可信

- **验证观测通道：** 缺少反馈时先检查入口与日志，用最小探针确认目标路径被触达；不拿单元测试通过外推集成、性能或实机体验。
- **避免自证：** 用独立期望、真实输入核对结果；目标变化时同步更新验收标准，不降低标准掩盖失败。
- **区分预检与回退：** `dry-run` 是预检，不是回退；本地备份不能撤销远端副作用。不可逆动作须提前明确验证渠道与失败处置。

## 延迟、噪声与停滞处置

| 观测状态 | 下一步动作 |
| --- | --- |
| 后台任务运行中、尚无反馈 | 保留任务标识，做独立工作或等待通知；未判明失败前不重复启动。 |
| 超出预期时间 | 检查状态与日志，区分延迟、挂起与失败后再决定等待或重试。 |
| 结果偶发波动或矛盾 | 控制环境与输入，核查采样方式；用有依据的复测辨别噪声。 |
| 反复重试无新证据 | 停止原样重试；列出已排除假设，换观测点或缩小实验范围。 |
| 确缺外部权限、资源或决定 | 完成可独立准备的工作，针对受阻步骤提出具体请求。 |

## 与其它技能的分工

- `using-superpowers`：按任务与误差选择技能及开发模式。
- `brainstorming` / `writing-plans`：明确目标契约，拆解可独立验证的小步。
- `test-driven-development` / `runtime-driven-development`：通过自动运行或实机探针获取闭环反馈。
- `systematic-debugging`：用可控实验定位根因。
- `verification-before-completion` / `finishing-a-development-branch`：核查完成证据并收尾交付。
