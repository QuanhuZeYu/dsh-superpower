# 排查 Superpowers

## 概述

与使用者一起钉死一次会话里到底出了什么问题，读磁盘上的会话记录，然后用证据报告发生了什么。
你只报告，不诊断 Superpowers。由分诊 bundle 的人决定 Superpowers 是否要改。

**核心原则：** 每条发现都引用 `path:line`。没有引用就没有发现。每个数字都来自会话记录
或你实际跑过的命令，绝不来自记忆。

## 工作流

每个步骤建一条 todo（用 `todo_write`，每次提交完整清单）。步骤 5–6 只在其所述条件下运行。

1. **受理问题。** 一次问一个问题，直到你能写出一段陈述，点名会话、已知的轮次范围、使用者
   期望什么、实际发生了什么，以及他在意的可观测指标（墙钟时间、token、重复动作、某个具体
   动作）。"花了太久"是抱怨，不是问题陈述。记下目标是否是一份可分享的问题报告。
2. **定位。** 按 `references/session-discovery.md` 把每个会话解析成已核实的绝对文件系统路径。
   用首个提示词与时间戳确认历史会话，并列出你排除的每个候选及原因，没有就写"无"。枚举关联的
   子代理会话。创建 `~/.dsh/diagnosing-superpowers/<session-id>/`，把路径告诉使用者，在其中
   填写 `templates/case.md`，遵守它关于环境与技能观测的溯源规则。
3. **分诊。** 自己读所报问题附近的记录。然后每个维度并发派发一个分析子代理（`subagent`），
   各自拿到 case 文件路径、`prompts/analyst-common.md`，以及 `prompts/` 里的一个维度文件：
   `skill-timeline.md`、`plan-adherence.md`、`repeated-work.md`、`stumbles.md`、
   `quality-evidence.md`、`request-conflicts.md`、`cost-and-time.md`。记录很长时按轮次范围
   拆分同一维度。丢弃任何没有 `path:line` 的返回发现。
4. **报告。** 按顺序填满 `templates/report.md` 的每一节，写到工作区，展示出来，并给出路径。
   检查被引用的内容实际证明了什么，并保留支撑它的 case；符号链接别名不是冗余副本。
5. **导出** —— 仅当使用者要 bundle 时才做；绝不在未被要求时自行打包。如果受理阶段的目标就是
   一份问题报告，只说一次"可按需产出脱敏 bundle"，然后等待。询问脱敏级别，说明各自包含什么：
   skeleton（不含工具结果正文）、evidence（仅被引用事件的正文）、full（全部保留）。按
   `templates/bundle-README.md` 构建 bundle，派发 `prompts/scrub.md`，再派发
   `prompts/scrub-audit.md`，两者反复执行直到审计返回 CLEAN。在展示最终的 scrub 日志、文件
   清单以及隐私与证据结论之前，先完成 bundle 模板里的证据检查与对账。仅在批准后才归档（用
   Python 的 `zipfile` 或 Node 等价脚本打包）。给出归档路径时，说明它包含什么，指出 scrub
   日志记录替换情况的地方，并说明脱敏可能漏掉东西：分享之前使用者必须逐文件复核。
6. **相似会话** —— 被要求时。把已确认的发现变成签名，按 mtime 与大小列出候选，找到标记行号，
   对每个候选并发派发 `prompts/similar-session.md`，并追加报告 §9。

## 速查

七个分析维度永远都跑。这张表只说明步骤 3 里你自己该先读哪块区域、结论里该先讲哪些发现。

| 抱怨 | 先读、先讲 |
|---|---|
| "花了太久" | cost-and-time、stumbles |
| "它为什么多做这些活？" | repeated-work、plan-adherence |
| "为什么这么贵？" | cost-and-time |
| "它到底在干什么？"（还在跑） | skill-timeline；在覆盖说明里标注"仍在进行中" |
| "它无视了计划" | plan-adherence，先看压缩事件行 |
| "技能 X 从没被触发" | skill-timeline |

## 硬性规则

- **上下文安全。** 一行会话记录可能有一兆字节。对每个会话文件、每一次，都遵守
  `references/context-safety.md`。
- **只读。** 绝不修改、移动或删除会话文件。
- **给子代理的路径要精确。** 子代理的"当前会话"是它自己的。传绝对路径与 id。
- **只有人类提示词算数。** 注入的 system-reminder、插件消息与工具结果不是使用者的话。在
  子代理的记录里，"user" 是父代理。
- **不做 Superpowers 诊断。** 报告 §7 只陈述相关性，就此打住。绝不点名某个技能的缺陷，也不
  提议改动。使用者逼你要修复方案也不豁免这条；指出报告 §7，并说明可按需产出 bundle。也不
  给使用者建议。
- **批准闸门。** 使用者看过 scrub 日志与文件清单之前，不得归档。
- **先受理，再分析。** 使用者回答之前，步骤 2–6 一概不启动。如果他不在，把问题写下来然后
  停下。你替他重建出的陈述不是回答。已经明确范围的请求——某个具体事件、当前在跑什么、或
  指定要跑的分析——本身就是陈述：先回答它，再提问。对整个会话问"为什么"是抱怨。

## 危险信号

| 想法 | 现实 |
|---------|---------|
| "问题很明显，跳过受理" | 问题陈述决定一切的范围。去问。 |
| "他不在，那我就把陈述重建出来" | 你重建不出他想要什么。把问题写下来然后停下。 |
| "我现在全库扫一遍，最后再问" | 无范围的清扫会把他的预算花在错误的问题上。先问。 |
| "他想要一份问题报告，那我现在就把 bundle 建出来" | bundle 是他的会话数据打包。只在他要求时才建。 |
| "改动很小、很局部，不需要重构" | 不管多小，这不是你说了算。报告证据；由分诊者决定。 |
| "每个 token 的单价众所周知" | 你没从会话记录里算出来的数字就是编的。引用，或者删掉。 |
