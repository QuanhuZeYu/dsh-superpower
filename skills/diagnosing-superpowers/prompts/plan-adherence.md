维度：计划遵循

还原会话当初约定好的计划，再把每个计划步骤映射到实际发生的事。这里的"计划"指任何约定的行动
路线，不是 git commit。

1. 找到约定的计划：聊天里商定的设计或计划（看人类说"好 / 可以 / 继续"之前的助手文本）、会话
   期间写下的 spec 或计划文件（写 `docs/`、`plans/`、`specs/` 下或人类点名文件的工具调用）、
   含义已在 case 文件里确立的 todo 记录（DSH 里是 `todo_write` 调用），或助手文本里的任何
   编号清单。引用每个计划步骤及其 `path:line`。
2. 标出计划与执行之间的结构性事件：discovery 阶段识别的压缩事件、恢复、被中止的轮次，以及
   关联会话的派发。记下它们的行号；紧跟这些事件之后的计划漂移是独立的一条发现。
3. 对每个计划步骤，找出执行它的工具调用与助手文本，或确认没有任何东西执行它。报告：
   - 跳过的步骤（找不到执行；引用该计划步骤）；
   - 乱序执行的步骤（行号显示顺序）；
   - 被悄悄改掉的步骤（执行与计划步骤不一致，而助手从未声明；两处都引用）；
   - 凭空多出的步骤（做了没有任何计划步骤覆盖的工作）；
   - 紧跟结构性事件之后的漂移（引用该事件行与第一个偏离的动作）。
4. 如果没有可还原的计划，就把它作为唯一的发现说出来，并给出你检查过的行。
