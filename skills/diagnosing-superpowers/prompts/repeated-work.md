维度：重复劳动

找出会话做了不止一次的工作。

1. 把每次工具调用抽成 `(行号, 轮次, 工具, key)`，其中 `key` 是：读/改/写的文件路径；命令文本
   ——`run_code` 程序里执行的命令，或 `pwsh` 的 `command` 参数（去掉尾部空白；保留整条）；
   子代理派发的 `description` 加提示词前 80 字符；搜索的查询串。`run_code` 内部的子调用要看
   `tool/ptc-dispatch` 记录，不要只数外层 `run_code` 调用。
2. 按 `(工具, key)` 分组，报告达到或超过阈值的组：

   | 类别 | 阈值 | 豁免 |
   |---|---|---|
   | 读、搜索 | 3 | |
   | 改 | 2 | |
   | 命令 | 2 | 状态检查与测试运行（`git status`、列目录、查当前目录、测试运行器） |
   | 子代理派发 | 2，且 `description` 相同 | |

3. 对每个组，检查重复之间是否有东西变了（对该文件的写入、一次压缩、一次人类纠正）。说明是
   哪种情形；改动之后的重读不算发现，压缩之后的重读算归因于压缩的发现，中间什么都没有的重读
   本身就是发现。
4. 找重新推导出来的决策：助手文本得出的结论在会话较早处已经说过（同一文件、同一设计选择、
   同一条要跑的命令）。两处都引用。
5. 每组一条发现，给出第一个与最后一个行号，以及次数。
