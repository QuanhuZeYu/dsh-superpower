# Superpowers 会话诊断 bundle

会话：<session-id>
Harness：<名称> <版本>（<溯源标签>）    Superpowers：<版本>（<sha 或"不是检出目录">；<溯源标签>）
脱敏级别：skeleton | evidence | full
构建时间：<ISO 时间戳>

把头部的版本字段标注为历史证据、未经验证的快照、当前观测或未知。`environment.json` 对每个
环境字段与其支撑位置携带同样的溯源区分。

## 这是什么

一份经过脱敏的编码代理会话记录，该会话装了 Superpowers 且出了问题。它让当时不在场的代理或人
判断 Superpowers 是否有责任、若有该改什么。里面的报告用 `path:line` 证据说明发生了什么。按设计
它不含对 Superpowers 的诊断，也不含修复提议；那是读者的事。

## 文件

- `report.md` — 诊断报告（问题陈述、结论、环境、会话、时间线、发现、相关性、覆盖说明）。
- `case.md` — 分析者据以工作的 case 文件。
- `environment.json` — 环境一节的机器可读副本。
- `timeline.md` — 逐轮次时间线。
- `findings/<维度>.md` — 各维度的原始分析发现。
- `transcripts/<session-id>.md` — 每个被检查会话的逐轮次精简呈现（绝不是原始 `.jsonl.zstd` /
  `.jsonl`）。按级别保留工具结果正文：

  | 级别 | 工具结果正文 |
  |---|---|
  | skeleton | 有意限制；替换成 `[tool result: <tool>, <bytes> bytes, exit <code>]` |
  | evidence | 保留被引用事件，包括支撑发现所需的命令与结果 |
  | full | 全部保留 |
- `scrub-log.md` — 用过的每个占位符及其类别（绝不含原始值）。

## 怎么读

从 `report.md` §1–2 开始，再看 §7（相关性）及它引用的证据行，然后看 `transcripts/` 里对应的
轮次。`path:line` 指向报告者机器上的原始文件；精简后的记录用 `[L<n>]` 标记保留同样的行号。

## 脱敏

占位符形如 `<EMAIL-1>`、`<PERSON-2>`、`<SECRET-3>`、`<HOST-4>`、`<REPO-5>`、`<ORG-6>`、
`<PROPRIETARY-7>`；家目录路径改写为 `~/…`。同一个占位符在本 bundle 内始终指同一个原始值。

## 生产者说明

完成后的 bundle 会用实际结果替换这些说明。

脱敏之后，只用本 bundle 检查每一条被导出的实质发现：把它的引用解析到某个被收入的记录或来源
标记上，读被引用的命令、结果或引文，并核实它支撑该论断。仅证明路径与行存在是不够的。当脱敏级别
或必要的保留去掉支撑时，记录具体限制。

对报告、case、环境、发现、README 以及任何本地问题草稿做对账。用最终文件（不含日志本身）刷新
scrub 日志的次数。移除过期的导出声明；区分 bundle 的准备与归档的交付。保留从历史锚点到已收入
证据的映射。

把独立的隐私审计与证据有用性分开记录：
- 隐私审计：CLEAN 或未解决的遗漏。
- 证据支撑：有支撑或受限，并给出受影响的发现与原因。

如果检查之后内容有变化，重做受影响的检查。为现有的归档批准呈现最终日志、文件清单与两项结论。
归档审阅过的文件，并核实交付的归档与它们一致。把归档交付记录在受审阅 bundle 之外，而不要在批准
之后改动它的内容。脱敏不是穷尽的隐私认证。
