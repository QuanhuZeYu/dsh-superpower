# 派发并行子代理

**核心原则：** 将相互独立的问题域分别委派给隔离上下文的子代理（`subagent`）并发执行，主控保留上下文负责协调与整合。

## 适用边界

- **使用时机：** 2 个及以上独立的失败或子任务（如不同测试文件、互不依赖的子系统），彼此无共享可变状态、无顺序依赖，且无需修改同一批文件。
- **禁止使用：** 故障彼此关联（修好一处可能连带解决其余）、处于尚未定位问题域的探索阶段、或子代理会竞争同一文件/资源。

## 执行步骤

### 1. 按独立问题域分组
将失败或任务按子系统/文件边界拆开，确认各组修改互不干扰。

### 2. 构造自包含提示词
子代理不继承当前会话历史，每个提示词必须包含：
- **聚焦范围与目标：** 指定具体测试文件或模块、贴出完整报错信息与期望结果。
- **明确约束：** 限定可修改的文件范围（如“仅修改该模块或对应测试，禁止跨模块重构”），要求根因修复（如用事件等待替代随意加大超时）。
- **产出契约：** 要求返回根因、具体改动文件与验证结果摘要。

### 3. 并发派发
在同一轮执行中发起所有独立子代理（DSH 后台 `subagent` 并发运行；需任务板协作时可用 Agent Teams：`spawn_teammate` + `team_task_*` + `send_message` + `wait_agent`）。

### 4. 评审与整合验证
全部子代理返回后：
1. 审阅各子代理报告与 `git diff`，确认未越界或产生隐性冲突。
2. 运行完整测试套件与项目必需检查，验证所有改动协同工作。
