# 实现者子代理提示词模板

派发实现者子代理（`subagent`，独立上下文）时使用本模板：

```
子代理（subagent，独立上下文）：
  description: "实现任务 N：[任务名]"
  model: [MODEL — 必填：按 SKILL.md「模型选择」指定，省略会静默继承昂贵主模型]
  prompt: |
    你正在实现任务 N：[任务名]
    工作目录：[directory]

    ## 需求与上下文
    1. 先读任务简报：[BRIEF_FILE]（唯一需求来源，确切取值、签名与用例一律原样采用；不要读整份计划）
    2. 上下文与前序接口：[场景铺垫、前序任务产出的接口签名、主控已作出的台账裁决]

    ## 执行规则
    - **自主处理可逆细节：** 局部命名、内部结构按代码库既有模式直接决定；仅当缺少会改变目标、外部契约或造成不可逆后果的决定时，才以 NEEDS_CONTEXT 提问。
    - **按开发模式推进：** 加载简报指定的 `test-driven-development` 或 `runtime-driven-development`。先跑通最小真实路径，再跑必要反例或实机探针；不要求先写失败测试或删除正确实现。迭代时跑聚焦测试，提交前跑相关套件。
    - **严禁派生子代理：** 全部工作亲自完成，绝不派发帮手或评审子代理（主控会在你回报后统一安排独立评审）。
    - **代码边界：** 遵循计划文件结构，保持单文件职责聚焦；错误处理放在负责边界，不为内部已校验契约堆砌冗余兜底。若既有文件已严重臃肿，小心修改并在报告中记为顾虑。
    - **提交前自审：** 对照简报检查需求完整性、YAGNI、真实行为测试/实机证据（含关闭临时诊断后的交付配置复测）及输出干净度，发现问题立即修掉再提交。
    - **修复轮恢复：** 若被主控带着评审发现恢复，按原任务模式修复并验证，将修复记录追加到 `[REPORT_FILE]` 末尾后按同样简短格式回报。

    ## 报告契约
    将完整报告写入 [REPORT_FILE]：
    - 实现内容（或受阻时已尝试的实验）、修改的文件、自审发现
    - **TDD 证据**（若适用）：最小真实路径命令与输出、反例与回归结果
    - **运行时证据**（若适用）：目标实例版本/配置、输入与探针命中、修复前后同场景对比、关闭临时诊断后的交付配置复测及原始记录位置（未跑则写未验证，严禁编造）
    - 计划/规格版本、提交 SHA、工作树状态、证据失效条件及剩余顾虑

    最终回复主控时控制在 15 行以内：
    - **状态：** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT（验证缺失或缺陷未解时继续工作，仅硬资源受限或缺外部依赖用 BLOCKED，缺契约决定用 NEEDS_CONTEXT）
    - **提交：** 短 SHA + 标题
    - **验证摘要：** 一行测试/实机结果
    - **顾虑 / 阻塞点：** 具体说明（如有）
    - **报告路径：** [REPORT_FILE]
```
