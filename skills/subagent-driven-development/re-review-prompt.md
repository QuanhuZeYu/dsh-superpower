# 范围受限的复评审提示词模板

修复轮次完成后，派发范围受限复评审子代理（`subagent`，独立上下文）使用本模板：

```
子代理（subagent，独立上下文）：
  description: "复评审任务 N 修复轮次 R"
  model: [MODEL — 必填：小修复 diff 用便宜至中档模型]
  prompt: |
    你在复评审一个任务的修复轮次：验证上轮发现是否已解决，并检查修复 diff 是否引入新破坏。

    ## 输入材料
    - **任务简报：** [BRIEF_FILE]
    - **待验证发现：**
      [FINDINGS]
    - **实现者报告（末尾含追加的修复记录）：** [REPORT_FILE]
    - **修复 Diff：** [FIX_BASE_SHA]..[HEAD_SHA]，评审包文件：[DIFF_FILE]

    ## 评审规则
    - **只读且范围受限：** 读取 [DIFF_FILE]，绝不修改工作树，绝不派生子代理。聚焦于待验证发现与本次修复 diff，不无故扩成全库重审。
    - **范围外严重问题不豁免：** 若观察到修复 diff 之外的问题，写入「范围外观察」；凡危及安全、数据完整性或当前验收的，立即列为阻塞项（最终复评审同样适用）。
    - **核实修复证据：** 按简报模式（TDD 或 `runtime-driven-development`）核对追加的原始运行证据与代码 diff 是否吻合，不盲信文字声称。

    ## 输出格式（直接从第一条发现结论开始）

    ### 发现结论
    对每条待验证发现按序给出：
    - **[发现摘要]** — `ADDRESSED`（已消除）| `REFUTED`（证据已排除原报告路径，任何轮次均可判定）| `NOT ADDRESSED`（未解决或争议未决），附 `file:line` 与运行证据。

    ### 修复 diff 中的新增破坏
    - 附严重度（Critical / Important / Minor）与 `file:line`；无则写“无”。

    ### 范围外观察
    - 附证据、严重度、验收依赖及是否阻塞；无则写“无”。

    ### 结论
    **修复轮次：** [原发现已处理或被驳回，无当前验收缺口和严重问题 | 仍有发现未决（列出未决与阻塞项）]
```
