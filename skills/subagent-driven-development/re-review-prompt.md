# 范围受限的复评审提示词模板

在一次修复轮次之后派发复评审时使用本模板。复评审者验证发现是否已处理，并检查修复 diff 是否引入新破坏。它不是一次全新的评审——完整评审已经做过了。

**目的：** 验证上一次评审的每条发现都已处理，且修复本身没有弄坏任何东西。

```
子代理（subagent，独立上下文）：
  description: "复评审任务 N 修复轮次 R"
  model: [MODEL — 必填：按 SKILL.md 的「模型选择」挑选；省略
         model 会静默继承会话里最贵的那个]
  prompt: |
    你在复评审一个任务的修复轮次。上一次评审产生了
    发现；某个实现者尝试修复了它们。你的工作是
    对每条发现给出结论，并检查修复 diff——不做别的。

    ## 任务

    读任务简报：[BRIEF_FILE]

    ## 待验证的发现

    [FINDINGS]

    ## 修复

    读实现者的报告（修复报告追加在末尾）：
    [REPORT_FILE]

    **修复 base：** [FIX_BASE_SHA]（上一次评审看到的 head）
    **Head：** [HEAD_SHA]
    **Diff 文件：** [DIFF_FILE]

    把 diff 文件读一遍——它包含修复提交、统计摘要，
    以及带周边上下文的修复 diff。不要重跑 git 命令。
    如果 diff 文件缺失，自己取 diff：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 与
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    你对本次检出是只读的。绝不以任何方式改动工作
    树、索引、HEAD 或分支状态。

    ## 你不派发子代理

    本次评审的全部工作都由你自己做。绝不派生子代理评审 diff 的
    任何部分，也绝不为第二意见另派评审者。
    本流程已经为这项工作提供了它应得的每一个评审席位；你派的
    评审者在满额成本上重复其中一个，它的结论
    一文不值。如果 diff 大到一次读不完，
    就自己分几遍读，并在报告里说明。

    ## 范围

    你的范围是发现清单与修复 diff。对每条发现给出结论。
    检查修复 diff 中修复本身引入的新问题。不要
    复评审修复没有触碰的代码：如果你注意到完全
    位于修复 diff 之外的问题，把它报在「范围外观察」下——它
    不阻塞本任务，也不延长循环。宽口径的
    整分支评审会在所有任务完成之后进行。

    ## 测试

    实现者重跑了覆盖改动代码的测试，并把结果追加
    到了报告文件。把报告当作未经验证的主张：
    确认修复报告点名了覆盖测试并展示了它们的输出，
    并用 diff 验证这些主张。不要为了确认他们的报告而重跑
    测试套件。只在阅读代码引出具体疑问、且现有运行无法
    回答时才跑测试——而且只跑聚焦测试，绝不跑整包套件。

    ## 输出格式

    你的最终消息就是报告本身：直接从第一条
    发现的结论开始。每一行要么是结论、要么是带 file:line 的发现、
    要么是你做过的检查——不要开场白，不要过程叙述。

    ### 发现结论

    对「待验证的发现」里的每条发现，按顺序：
    - **[发现的一句话摘要]** — ADDRESSED | NOT ADDRESSED，附 file:line
      证据。“尝试过了”不等于已处理：那个具体的缺陷必须
      不再存在。

    ### 修复 diff 中的新增破坏

    修复本身弄坏或引入的任何东西，附严重度
    （Critical/Important/Minor）与 file:line。干净则写“无”。

    ### 范围外观察

    你注意到的、完全位于修复 diff 之外的问题。非阻塞；主控
    把它们记入台账留待最终评审。没有则写“无”。

    ### 结论

    **修复轮次：** [所有发现都已处理，无新的 Critical/Important
    破坏 | 仍有发现未决] —— 列出未决项。
```

**占位符：**
- `[MODEL]` — 必填：按 SKILL.md 的「模型选择」选评审者模型；针对小修复 diff 的
  范围受限复评审用便宜到中档的模型
- `[BRIEF_FILE]` — 任务简报文件（与实现者用的是同一个文件）
- `[FINDINGS]` — 上一次评审给出的 Critical/Important 发现与规格缺口，
  逐字复制，每条一个列表项
- `[REPORT_FILE]` — 实现者的报告文件（修复报告追加在后面）
- `[FIX_BASE_SHA]` — 上一次评审看到的 head
- `[HEAD_SHA]` — 当前提交
- `[DIFF_FILE]` — `python scripts/review-package.py PLAN_FILE FIX_BASE HEAD` 打印的路径

**复评审者返回：** 逐条发现的结论（ADDRESSED / NOT ADDRESSED）、
修复 diff 中的新增破坏、范围外观察，以及本轮结论。
