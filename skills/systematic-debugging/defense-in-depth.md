# 按失败路径放置防护

## 原则

**先修根因，再把必要防护放到负责该失败的独立边界。** 层数不是质量指标：内部已校验数据直接沿契约使用，无需把每个调用者都变成校验器。

## 责任边界划分

| 场景 | 最小处理 |
| --- | --- |
| 外部输入、反序列化或第三方响应进入系统 | 在入口解析并校验，向内部提供明确类型与契约 |
| 内部传递已校验且未失效的数据 | 直接按契约使用；若出现非法值，修复产生该值的源头 |
| 存在绕过入口的另一条可达路径，或中间变更使原校验失效 | 在该新边界补检查，说明其独立覆盖的失败路径 |
| 文件、网络或设备 I/O 可能失败 | 由操作层返回具体错误，在能恢复、补充上下文或通知用户的位置处理 |
| 权限、资金、删除等高风险状态变更 | 按具体不变量保障授权与原子性，不因入口做过格式校验而省略业务鉴权 |
| 开发期验证内部不变量 | 使用无副作用、可关闭的断言或针对性探针，收尾时按运行时模式复测 |

## 新增防御前先核对

- **明确依据：** 指出具体触发路径、现有边界为何未覆盖、以及新增防护改变什么可见行为。
- **拒绝静默掩盖：** 自动重试仅限幂等的暂时性故障且有界；fallback 须对应真实产品契约，不静默吞掉异常或返回假成功。
- **示例：** 若测试 helper 在 `beforeEach` 前返回空目录 `''` 导致 `git init` 跑在源码目录，最小修复是让 helper 未初始化时直接在源头抛错；内部已消费合法目录的函数无需逐层重复判空。
