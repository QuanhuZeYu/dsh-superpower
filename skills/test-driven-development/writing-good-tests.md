# 编写好测试

编写或修改测试、添加 mock 或测试辅助函数时加载本参考。两条核心原则：

1. **每个测试都必须点明它能抓住的那处业务破坏（bug，而非有意重构）。**
2. **每个测试都尽可能跑真实组件与真实数据。**

## 原则 1：点明要抓的破坏

动笔前先回答：**什么样的生产代码 bug 会让这个测试失败？**

- **手工推导字面量期望：** 禁止调用被测代码或其共用 builder 计算 `expected`。
  ```typescript
  // ❌ 镜像断言：两边调同一个函数，永远相等
  expect(buildSearchQuery({ tag: 'urgent' })).toBe(buildSearchQuery({ tag: 'urgent' }));
  // ✅ 独立字面量期望
  expect(buildSearchQuery({ tag: 'urgent' })).toBe('tag:"urgent"');
  ```
- **测行为，不做变更探测器：** 不测内部常量值、私有结构或源码字面文本（不用 `grep` 测脚本/配置，而是用受控输入运行并断言输出或副作用）。
- **测自己的边界契约，不测框架：** 断言你注册的路由、发出的查询与产出的载荷，不测上游框架已担保的派发机制。纯 getter/转发无需单测，直接测首个依赖它的消费者结果。

## 原则 2：跑真实的东西

- **不对 mock 下断言：** 断言 `screen.getByTestId('sidebar-mock')` 只证明 mock 存在。要断言真实组件行为；若发现自己在测 mock，取消 mock 或删掉断言。
- **在最底层的慢操作/外部 I/O 处 mock：** 先摸清被替换方法的副作用，保留测试依赖的真实状态变更（如配置写入），只 mock 底层的慢服务启动或网络请求。
- **Mock 返回值须完整镜像真实结构：** 补齐文档化字段，避免下游读取省略字段时在集成环境静默崩溃。
- **生产代码不挂测试专属方法：** 仅供测试使用的清理逻辑（如 `destroy()`）放进测试辅助工具，不污染生产类。当 mock 搭建超过测试本身一半篇幅时，改用真实组件集成测试。

## 快速自检表

| 警告信号 | 修正方式 |
| --- | --- |
| 搭建与断言共用同一对象或计算逻辑 | 换成手工核对的字面量 fixture |
| 删掉或重构私有辅助函数测试就挂，但业务未坏 | 改为断言外部可见输出或状态变化 |
| 断言 `*-mock` 存在，或 mock 搭建比断言还长 | 取消 mock，改测真实组件集成路径 |
| 为凑覆盖率或流程形式而给简单代码补测试 | 删掉无价值测试；仅保留能防住真实回归的用例 |
