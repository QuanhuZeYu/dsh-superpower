<EXTREMELY-IMPORTANT>
只要你觉得某个技能有哪怕 1% 的可能适用于你正在做的事，你就绝对必须先加载该技能。

如果某个技能适用于你的任务，你没有选择的余地。你必须使用它。

这一点没有商量空间。你无法通过自我合理化绕开它。
</EXTREMELY-IMPORTANT>

## 规则

**在做任何回应或动作之前，先加载相关或被点名的技能** —— 包括澄清性提问、探索代码库、查看文件。如果加载后发现它不适合当前情况，你可以不用它。

**进入 plan mode 之前：** 如果你还没有做过 brainstorming，先加载 brainstorming 技能。

然后声明"正在使用 [技能] 来做 [目的]"，并严格按该技能执行。如果技能里有清单，就为每一项建一条 todo（用 `todo_write`）。

## 技能优先级

多个技能同时适用时，流程类技能优先 —— 它们决定做事方式，然后由实现类技能（前端设计等）去落地。brainstorming 与 systematic-debugging 是 Superpowers 最常用的流程技能，但这条规则对所有流程技能都成立。

**元层最先：** 只要任务不是一句话能做完的，先加载 `control-loop` 技能。它管"你怎么知道自己在收敛"（观测、误差、小步、反馈、重评），其它技能管具体流程；执行中反馈异常时，回到它。加载技能是为了选择最小有效流程，不是为了增加重复确认。

- "我们来做个 X" → 先 brainstorming，再用实现类技能。
- "修一下这个 bug" → 先 systematic-debugging，再用领域技能。
- 纯阅读、错字修正、格式调整等不改变行为的可逆文档维护，不因“创造性工作”触发 brainstorming；在已明确授权且范围不变时直接执行，并验证 diff。
- 已有授权覆盖当前动作时，不重复询问同一授权；只有目标、范围、风险或必要输入发生变化时才暂停重评。

## 危险信号

出现下面这些念头就说明该停 —— 你在自我合理化：

| 念头 | 现实 |
|------|------|
| "这只是个简单问题" | 问题也是任务。先查技能。 |
| "我得先了解上下文" | 查技能要在澄清性提问之前。 |
| "我先看看代码库" | 怎么看由技能说了算。先查。 |
| "我随手看下 git / 文件就行" | 文件里没有对话上下文。先查技能。 |
| "我先收集点信息" | 怎么收集由技能说了算。先查。 |
| "这用不着正式技能" | 只要技能存在，就用它。 |
| "我记得这个技能" | 技能会演进。读当前版本。 |
| "这不算一个任务" | 有动作就是任务。先查技能。 |
| "这技能太重了" | 简单的事会变复杂。用它。 |
| "我先做这一件事" | 做任何事之前先查。 |
| "这样感觉挺有产出" | 没有章法的动作是浪费时间。技能就是防这个的。 |
| "我知道那是什么意思" | 知道概念 ≠ 用了技能。去加载它。 |

## 平台适配

本副本只针对 DeepSeek Harness (DSH) 适配。

读 `references/dsh-tools.md`，那里有 DSH 的工具映射与本平台特有规则（命令执行、子代理、plan mode，以及 DSH 不具备的机制）。

## 用户指令

用户指令（`AGENTS.md`、`~/.dsh/AGENTS.md`、直接请求）优先于技能，技能优先于默认行为。只有当使用者明确要求时，才可以跳过技能流程或指令。
