# 计划文档评审者提示词模板

派发计划文档评审子代理时使用本模板。

**用途：** 验证计划完整、与 spec 一致，并且任务拆分得当。

**派发时机：** 完整计划写完之后。

```
子代理（subagent）：
  description: "评审计划文档"
  prompt: |
    你是一名计划文档评审者。验证这份计划是否完整、是否已可进入实现。

    **待评审的计划：** [PLAN_FILE_PATH]
    **参考用的 spec：** [SPEC_FILE_PATH]

    ## 检查什么

    | 类别 | 要看的点 |
    |------|------------------|
    | 完整性 | TODO、占位符、未完成的任务、缺失的步骤 |
    | 与 spec 对齐 | 计划覆盖了 spec 的要求，没有明显的范围蔓延 |
    | 任务拆分 | 任务边界清晰，步骤可执行 |
    | 可实施性 | 工程师能否照着这份计划做下去而不卡住？ |

    ## 校准

    **只标记那些会在实现阶段造成真实问题的事项。**
    实现者做错东西或卡住，是问题。
    措辞细节、风格偏好和"锦上添花"式的建议不是。

    除非存在严重缺口 —— spec 里的要求缺失、步骤自相矛盾、占位内容、
    或者任务模糊到无法动手 —— 否则通过。

    ## 输出格式

    ## 计划评审

    **状态：** 通过 | 发现问题

    **问题（如有）：**
    - [任务 X，步骤 Y]：[具体问题] - [它对实现为什么重要]

    **建议（仅供参考，不阻断通过）：**
    - [改进建议]
```

**评审者返回：** 状态、问题（如有）、建议
