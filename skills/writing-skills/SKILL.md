# 编写技能

**核心原则：** 技能是针对可复用技术、模式或工具的紧凑参考指南（不是某次排错的记叙文）。用可复核反馈改善文档；不把推演写成测试结果，不把规则服从等同于用户验收通过。

个人技能位于 `~/.dsh/skills/<skill-name>/SKILL.md`，项目技能位于 `<项目根>/.dsh/skills/<skill-name>/SKILL.md`（DSH 仅扫描技能根下一层目录）。补充参考见同目录 `anthropic-best-practices.md`。

## 1. 结构与 Frontmatter 规范

- **YAML Frontmatter（总长 ≤ 1024 字符）：**
  - `name`：英文小写字母、数字与连字符（kebab-case，推荐用动名词或核心洞察命名，如 `condition-based-waiting`、`root-cause-tracing`）。
  - `description`（≤ 500 字符，第三人称）：**只写触发条件（“当/在……时使用” + 具体症状与上下文），绝不概括技能的工作流或步骤！**（测试证实：一旦在 description 中概括工作流，代理会走捷径照着摘要做而跳过技能正文）。
- **文件拆分原则：** 原则、概念与 < 50 行的代码模式直接内联在 `SKILL.md`；超过 100 行的 API/语法重型参考或可复用脚本拆分为同目录独立文件（脚本须写明用解释器调用，如 `python scripts/foo.py` 或 `node scripts/bar.js`，避免可执行位丢失）。

```markdown
---
name: skill-name-with-hyphens
description: 当[具体触发条件、症状与上下文，不含工作流概括]时使用
---

# 技能名
## 概述（1-2 句核心原则）
## 使用时机与边界（仅在分支复杂时用小型 dot 流程图）
## 核心模式 / 步骤（含精炼正反代码对比或快速参考表）
## 常见误区对照
```

## 2. Token 效率与交叉引用

高频技能会被反复加载进会话上下文，每一处冗余都会持续消耗 token：
- **严控篇幅：** 入门工作流目标 < 150 词，高频技能 < 200 词，普通技能 < 500 词。
- **消除重复：** 一个模式只给一个高质量、可直接改编的单语言示例（测试用 TS/JS，调试与脚本用 Python）；参数细节指向 `--help` 或独立参考文件。
- **正确交叉引用：** 引用其它技能时写 `**必需子技能：** 使用 test-driven-development`，**严禁使用 `@skills/...` 语法**（`@` 会立即强制加载全文并消耗大量上下文）。
- **克制使用流程图：** 仅在非直观的分支决策或易过早退出的循环处使用 `dot` 流程图（规范见 `graphviz-conventions.dot`，可用 `node ./render-graphs.js ../some-skill` 渲染 SVG）；线性步骤一律用编号列表。

## 3. 让措辞形式匹配失败类型

修改指导语前先确认误差类型，避免把所有问题都写成冗长的禁止清单或层层叠加的免责门禁：

| 观察到的基线问题 | 优先采用的形式 | 应避免的形式 |
| --- | --- | --- |
| 在时间/权威压力下明知故犯跳过规则 | 明确禁止性规定 + 常见借口对照表 | 软性建议（“最好/可以考虑”） |
| 遵守了规则，但产出臃肿、埋没结论或漏要素 | 正面结构契约（明确写出由哪几节组成、填哪些槽位） | 大段散文提醒或纯禁止清单 |
| 行为取决于特定上下文状态 | 以可观察条件为键的条件表（“当 X 时 → 执行 Y”） | 无条件铁律 + 大量补丁豁免条款 |
| 代理用防御性免责声明代替判断、令施工停滞 | 明确作者承担可逆决策、限定错误处理归属与有限验收 | 要求每步声明“未验证/不保证” |

## 4. 证据闸门与验证闭环

严格区分 **目标**（运行前定义的用户结果、成本与边界）、**预测**（待验证假设）与 **观测**（真实 `subagent` 原始输出或命令记录）：

- **按改动性质选择验证：**
  - **静态矛盾、失效链接或格式精简：** 直接对照原文与引用完整性修正并复核（不要求人为制造行为失败，也不将纯静态修正宣称为行为改善）。
  - **行为规则修改：** 使用有界对照循环 —— 先在独立新上下文运行旧版（或无技能）基线并保存原始输出 → 针对观测到的目标差距做最小修改 → 在同场景新上下文运行新版复测，同时检查反例（不适用时是否及时停用）与调用成本。未复现问题时如实记“本次未复现”，严禁诱导造假 RED。
- **子代理对照测试与元测试方法：** 详见 [testing-skills-with-subagents.md](testing-skills-with-subagents.md)、[persuasion-principles.md](persuasion-principles.md) 与 [examples/AGENTS_MD_TESTING.md](examples/AGENTS_MD_TESTING.md)。
