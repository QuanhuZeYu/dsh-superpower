# 技能设计中的说服原则

说服原则可作为调整指导语气的候选工具，但**更强的语气既可能提高遵守率，也可能放大教条误用与无效返工**。是否有效必须以用户任务结果与成本验收为准（测试方法见 [testing-skills-with-subagents.md](testing-skills-with-subagents.md)）。

## 核心原则与适用边界

| 原则 | 在技能文档中的合理用法 | 必须避免的误用 |
| --- | --- | --- |
| **权威（Authority）** | 明确引用真实契约、铁律与适用前提 | 用“绝无例外”抹杀用户指令优先级或合理边界 |
| **承诺与一致性（Commitment）** | 要求显式声明所选路径、假设或台账裁决 | 强迫死守已证伪的初始判断、拒绝随反馈重评 |
| **稀缺与紧迫（Scarcity）** | 标明真实预算上限，优先消除关键误差 | 人为制造恐慌，或把所有检查都变成前置停工门禁 |
| **社会认同（Social Proof）** | 提供经过验证的推荐范式与正反对比模式 | 用“每次必然失败”等夸大断言替代具体机理说明 |
| **共同体（Unity）** | 对齐用户目标，鼓励基于证据的坦诚技术反驳 | 以“流程规范”名义压制合理的技术异议 |

## 措辞校准准则

1. **优先写清“可观察条件 → 最小动作 → 预期反馈”：** 绝大多数执行偏差源于条件不清或反馈缺失，而非语气不够凶。
2. **克制叠加禁令：** 当代理在某处卡住或给出防御性免责声明时，先删减互相冲突的前置门禁，不要再追加一张更长的禁止清单。
