# 用子代理测试技能

当创建或修改技能、需要验证指导语是否真正改善代理决策与任务产出时，使用本参考。

## 1. 运行前固定用户验收

验收标准来自用户目标、授权边界、产出质量与可接受成本（轮次、耗时、token），**不能从待测规则反推唯一答案**。规则服从度仅作诊断信息：若遵守规则却导致停工空转、破坏已有成果或成本激增，仍属未达标。

测试场景须覆盖：(1) 典型正例；(2) 不应启用该规则的反例边界；(3) 与其它技能或用户指令同时存在时的组合优先级。

## 2. 可复现对照步骤

1. **保存基线：** 新建技能以“无技能”为基线；修改技能以“修改前旧版”为基线。
2. **独立上下文运行：** 用后台 `subagent` 在全新独立上下文运行基线与候选版本，保持任务提示词、模型与工具完全可比，仅改变待测技能文本（不得向新版额外暗示正确答案）。
3. **核查真实动作：** 先保存完整原始输出，再核对实际工具调用与交付物（仅复述规则或口头声称执行不算数）。若基线未出现目标问题，如实记录“本次未复现”，不诱导造红。
4. **开放式元测试（分歧诊断）：** 若新版仍失败，可开放追问：“哪些指导影响了你的决定？哪处存在歧义或与任务冲突？什么条件会改变你的选择？”——将回答作为待验证假设修正条款，不直接照抄代理原话当规则。

## 3. 最小记录格式

```text
运行标识与条件：<subagentId、模型、工具与预设预算>
用户验收与失败定义：<运行前登记的目标与边界>
基线 vs 候选版本：<完整提示词与技能版本快照路径>
原始输出与直接观察：<完整 transcript 路径、实际工具动作与轮次成本>
结论：<达到验收 / 失败 / 本次未复现 / 未验证，及受影响引用复核结果>
```
